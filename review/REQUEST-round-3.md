## 봐줄 것 다섯 가지

### 1. 번호 재배치 무결성

기존 1~20장과 `docs/부록/A-FE-BE-용어-대응표.md`에 남은 `N장` 참조가 **실제로 그 내용을 다루는 장**을 가리키는지 확인해 주세요.

- 3장의 CORS 관련 참조 → 37장(API 레이어와 인증)이어야 함
- 18장의 성능 관련 참조 → 25장(렌더링 성능)이어야 함
- 10장의 App Router 참조 → 30장, CI 참조 → 23장

어긋난 것을 찾아주세요.

### 2. 개념 부채 — 이번 재배치의 최대 위험

새로 쓴 24~27장이 **아직 안 배운 개념**에 기대고 있는지 봐주세요.

SSR, 하이드레이션, 서버 컴포넌트, TanStack Query는 전부 **28장 이후**로 밀렸습니다. 24~27장에서 이것들을 설명 없이 전제하면 집필 원칙 2번 위반입니다.

### 3. 새 21~27장의 기술적 사실 오류

React 19와 현재 브라우저 기준으로 봐주세요.

- 21장 — node_modules 해석 알고리즘, 유령 의존성, pnpm 링크 구조, `npm ci`
- 22장 — 트리 셰이킹 조건, 트랜스파일이 타입 검사를 하지 않는다는 서술, 코드 스플리팅
- 24장 — Core Web Vitals 지표 정의와 임계값, INP 측정 방식, 75퍼센타일 기준
- 25장 — `memo`/`useMemo`/`useCallback`의 실제 동작, Profiler 사용법, React Compiler 설명
- 26장 — HTTP 캐싱 헤더 의미(`no-cache` vs `no-store`, `immutable`), `font-display`, 이미지 포맷
- 27장 — XSS, CSRF, CSP, `SameSite`, `HttpOnly`, 토큰 저장 위치 트레이드오프

### 4. 한글 가독성

긴 문장, 지시어가 모호한 곳, 번역투라서 두 번 읽어야 하는 문장.

### 5. 톤 일관성

기존 1~20장과 새 21~27장의 서술 톤, 그리고 장 구조가 일관적인지.

장 구조: `이 장의 질문` → `BE로 치면 이런 것` → `문제 상황` → 개념 → `흔한 오해` → `핵심 3가지` → `스스로 답해보기`
