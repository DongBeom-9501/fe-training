# 1. 이 문서를 읽는 법

> **이 장의 질문**: 나는 React를 이미 조금 쓸 줄 안다. 여기서 무엇을 더 얻는가?

## 이 문서가 답하려는 질문들

아래 질문에 자신 있게 답할 수 있다면 이 문서는 필요 없습니다. 하나라도 막힌다면 그 장부터 읽으세요.

| 질문 | 어디서 |
| --- | --- |
| 가상 DOM은 왜 직접 DOM을 만지는 것보다 빠른가? **정말 빠른가?** | 4장 |
| `setState`를 연달아 세 번 호출하면 리렌더가 세 번 일어나는가? | 10장 |
| 리스트의 `key`에 배열 인덱스를 쓰면 정확히 무엇이 깨지는가? | 6장 |
| `useEffect`의 의존성 배열에 함수를 넣으면 왜 무한 루프가 도는가? | 11장 |
| `useMemo`를 모든 계산에 붙이면 왜 오히려 느려질 수 있는가? | 13장 |
| 개발 모드에서만 API가 두 번 호출되는 이유는? | 8장 |
| Context를 쓰면 왜 관련 없는 컴포넌트까지 다시 그려지는가? | 14장 |

## 입문 가이드와의 관계

[입문 가이드](../../README.md)의 Part 4가 "React를 쓰는 법"이라면, 이 문서는 **"React가 그렇게 동작하는 이유"** 입니다.

```
입문 가이드 Part 4 (16~20장)     이 문서 (23장)
──────────────────────────      ──────────────────────
useState로 상태를 만든다    →    setState는 즉시 반영되지 않는다. 배칭과 스냅샷의 문제
useEffect로 데이터를 가져온다 →   useEffect는 생명주기가 아니라 외부 시스템과의 동기화 도구다
key를 넣어야 한다           →    key가 무엇의 동일성을 결정하며, 잘못 넣으면 무엇이 깨지는가
컴포넌트를 나눈다           →    나누는 기준은 재사용이 아니라 리렌더 경계와 상태 소유권이다
```

즉 이 문서는 **같은 주제를 한 단계 아래에서 다시** 봅니다.

## 관통하는 하나의 사고 방식

React를 정확히 쓰는 사람과 감으로 쓰는 사람을 가르는 것은 문법 지식이 아닙니다. **하나의 질문을 습관적으로 던지느냐** 입니다.

> **"지금 이 값은 렌더 사이에 살아남는가, 매번 새로 만들어지는가?"**

컴포넌트 함수는 렌더될 때마다 **처음부터 다시 실행됩니다.** 안에 선언된 변수도, 함수도, 객체도 전부 새로 만들어집니다. 그런데 어떤 것들은 살아남습니다 — `useState`의 값, `useRef`의 상자, `useMemo`가 기억한 결과.

이 문서에서 다루는 거의 모든 어려움 — 오래된 클로저, 무한 루프, 불필요한 리렌더, `useCallback`의 필요성 — 은 **살아남는 것과 새로 만들어지는 것의 경계** 에서 발생합니다.

지금 이해할 필요는 없습니다. 다만 각 장을 읽을 때마다 이 질문으로 되돌아오면 대부분 설명이 됩니다.

## 읽는 방법

**Part 1~3(2~14장)은 순서대로 읽으세요.** 렌더링 모델을 모르면 Hooks가 왜 그렇게 생겼는지 설명이 안 됩니다.

**Part 4~5(15~22장)는 필요한 것부터 읽어도 됩니다.** 설계와 실전 주제라 독립적입니다.

**23장은 마지막에 읽고, 그 뒤로는 체크리스트로 쓰세요.** 각 장에서 나온 안티패턴이 전부 모여 있습니다.

## 코드 규약

입문 가이드와 같습니다. 실습은 없고, 코드는 독해 대상입니다.

- 모든 예제는 **TypeScript + 함수 컴포넌트** 입니다. 클래스 컴포넌트는 다루지 않습니다
- 기준 버전은 **React 19** 입니다. 18과 달라지는 지점은 그때그때 표시합니다
- 나쁜 예에는 ❌, 좋은 예에는 ✅ 를 붙입니다

## 핵심 3가지

- **목표는 설명할 수 있게 되는 것입니다.** 입문 가이드의 같은 주제를 한 단계 아래에서 다시 봅니다.
- **관통하는 질문은 하나입니다.** "이 값은 렌더 사이에 살아남는가, 매번 새로 만들어지는가."
- **읽는 순서.** Part 1~3은 순서대로, Part 4~5는 필요한 것부터. 마지막 장은 체크리스트로 씁니다.
