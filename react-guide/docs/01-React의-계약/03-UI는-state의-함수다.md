# 3. `UI = f(state)` — 선언형이라는 계약

> **이 장의 질문**: "UI는 상태의 함수"라는 말은 은유인가, 문자 그대로인가?

## BE로 치면 이런 것

순수 함수를 떠올려 보세요. 같은 입력에 항상 같은 출력, 바깥을 건드리지 않음. 테스트하기 쉽고, 캐시하기 쉽고, 병렬 실행해도 안전합니다.

React 컴포넌트는 **그 순수 함수여야 합니다.** 이건 스타일 권고가 아니라 React가 성립하기 위한 전제 조건입니다.

```
컴포넌트(props, state) → 화면 설명
```

React는 이 함수를 **언제든, 몇 번이든, 도중에 멈추고 버렸다가 다시** 호출할 권리를 가집니다. (컴포넌트 사이의 렌더 순서 이야기입니다. 한 컴포넌트 **안** 의 Hook 호출 순서는 절대 바뀌면 안 됩니다 — 9장에서 다룹니다.) 그 권리가 있어야 렌더를 중단했다 재개하고(동시성), 개발 모드에서 두 번 호출해 검증하고(8장), 나중에 컴파일러가 자동 최적화할 수 있습니다(22장).

**당신이 순수성을 지키는 대가로 React가 그 모든 것을 해줍니다.** 이게 계약입니다.

## 문자 그대로 함수다

가장 자주 하는 오해부터 걷어냅시다. 컴포넌트는 인스턴스가 아닙니다. **함수이고, 렌더될 때마다 처음부터 끝까지 다시 실행됩니다.**

```tsx
function OrderRow({ order }: { order: Order }) {
  const label = `${order.id} (${order.status})`;   // 매 렌더마다 새로 계산
  const handleClick = () => open(order.id);        // 매 렌더마다 새 함수 객체
  return <tr onClick={handleClick}>{label}</tr>;
}
```

이 컴포넌트가 100번 렌더되면 `handleClick` 함수 객체가 **100개 만들어집니다.** 이전 것은 버려집니다.

Java의 객체 감각으로 접근하면 여기서 어긋납니다. 클래스의 메서드는 인스턴스당 하나지만, 여기서는 렌더당 하나입니다.

> **1장의 질문이 여기서 처음 실전이 됩니다** — "이 값은 렌더 사이에 살아남는가?" 위 코드에서 `label`도 `handleClick`도 살아남지 않습니다. `order`는 부모가 넘겨준 것이고, 살아남는 것은 오직 `useState`·`useRef`·`useMemo` 같은 훅이 붙잡고 있는 것뿐입니다.

## 렌더는 순수해야 한다

"순수하다"는 것은 구체적으로 이 세 가지를 뜻합니다.

**1) 같은 입력에 같은 출력**

```tsx
// ❌ 렌더할 때마다 결과가 다르다
function Greeting() {
  return <p>{Math.random() > 0.5 ? '안녕' : '반가워'}</p>;
}
```

**2) 바깥을 건드리지 않는다**

```tsx
let renderCount = 0;

// ❌ 렌더 중에 외부 변수를 수정한다
function Counter() {
  renderCount++;                    // React는 이 함수를 두 번 부를 수 있다
  return <p>{renderCount}</p>;
}
```

```tsx
// ❌ 렌더 중에 props를 수정한다
function Table({ orders }: { orders: Order[] }) {
  orders.sort((a, b) => a.amount - b.amount);   // 부모의 배열을 바꿔버림
  return <tbody>{orders.map(...)}</tbody>;
}

// ✅ 복사해서 정렬
function Table({ orders }: { orders: Order[] }) {
  const sorted = [...orders].sort((a, b) => a.amount - b.amount);
  return <tbody>{sorted.map(...)}</tbody>;
}
```

**3) 렌더 중에 부수 효과를 일으키지 않는다**

```tsx
// ❌ 렌더하면서 API를 호출한다
function OrderList() {
  const [orders, setOrders] = useState([]);
  fetch('/api/orders').then(r => r.json()).then(setOrders);  // 무한 루프
  return <Table rows={orders} />;
}
```

이 코드는 무한 루프입니다. 렌더 → fetch → setState → 렌더 → fetch → ... 부수 효과는 **렌더 밖** 으로 나가야 합니다.

## 부수 효과는 어디로 가는가

React 컴포넌트 안에서 부수 효과를 놓을 자리는 보통 이 두 곳입니다.

| 자리 | 언제 | 예 |
| --- | --- | --- |
| **이벤트 핸들러** | 사용자가 무언가 했을 때 | 저장 버튼 클릭 → POST 요청 |
| **`useEffect`** | 화면이 외부 시스템과 동기화되어야 할 때 | 웹소켓 연결, 구독, 외부 라이브러리 초기화 |

**순서가 중요합니다. 이벤트 핸들러를 먼저 고려하세요.**

React 공식 문서가 반복해서 강조하는 것이기도 한데, 초보자가 `useEffect`를 남용하는 이유가 "부수 효과 = useEffect"라고 외웠기 때문입니다. 실제로는 **대부분의 부수 효과는 사용자 행동에서 비롯되고, 그건 이벤트 핸들러에 씁니다.** 12장 전체가 이 이야기입니다.

## 스냅샷 — 렌더는 사진 한 장이다

이 개념이 `useState`의 모든 이상한 동작을 설명합니다.

**각 렌더는 그 시점의 state 값을 "찍어둔 사진"을 가집니다.** 렌더 안의 모든 코드는 그 사진 속 값을 봅니다. 나중에 state가 바뀌어도 **이미 찍힌 사진은 바뀌지 않습니다.**

```tsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log(count);   // 0 — 이 렌더의 사진 속 값
  };

  return <button onClick={handleClick}>{count}</button>;
}
```

클릭하면 `count`는 **3이 아니라 1이 됩니다.** 세 줄 모두 `count`가 0인 사진을 보고 있으니 전부 `setCount(0 + 1)`이기 때문입니다.

8장의 클로저(입문 가이드)가 여기서 실전으로 나타납니다. `handleClick`은 **이 렌더의 `count`를 클로저로 붙잡고 있습니다.**

해결책은 "최신 값을 기준으로 계산해줘"라고 함수를 넘기는 것입니다.

```tsx
setCount(c => c + 1);   // 3번 호출하면 실제로 3이 된다
```

> 10장에서 배칭과 함께 자세히 다룹니다. 지금은 **"렌더는 스냅샷이다"** 만 가져가세요.

## 이 계약이 주는 것

순수성을 지키면 React가 이런 것들을 대신 해줍니다.

| React가 해주는 것 | 순수성이 필요한 이유 |
| --- | --- |
| 바뀐 부분만 DOM 갱신 | 함수를 다시 불러 결과를 비교할 수 있어야 함 |
| 렌더 중단/재개 (동시성) | 중간에 버려도 안전해야 함 |
| 개발 모드 이중 실행 검증 (8장) | 두 번 불러도 같아야 함 |
| 자동 메모이제이션 (React Compiler, 22장) | 결과를 캐시해도 안전해야 함 |

**순수성을 어기면 이 기능들이 조용히 오작동합니다.** 에러가 나는 게 아니라 가끔 이상하게 동작합니다. 그래서 더 위험합니다.

## 흔한 오해

**"컴포넌트는 클래스처럼 인스턴스가 있다"**
없습니다. 함수 호출이 있을 뿐입니다. 상태는 컴포넌트 "안"이 아니라 React가 트리 위치별로 따로 보관합니다(7장).

**"렌더된다 = 화면이 다시 그려진다"**
아닙니다. 렌더는 "함수를 실행해서 결과를 얻는 것"이고, 실제 DOM 반영은 그 결과가 이전과 다를 때만 일어납니다. 5장에서 분리해서 봅니다.

**"부수 효과는 useEffect에 넣는다"**
절반만 맞습니다. **사용자 행동에서 비롯된 것은 이벤트 핸들러가 먼저입니다.**

**"state를 바꾸면 그 줄 다음부터 새 값이다"**
아닙니다. 그 렌더의 스냅샷은 끝까지 그대로입니다.

## 안티패턴 #2: 렌더 중에 props나 외부 상태 수정

```tsx
// ❌
function List({ items }) {
  items.sort(...);        // 부모의 배열을 파괴
  cache[items[0].id] = 1; // 외부 변수 수정
  return ...;
}
```

증상이 즉시 안 나타나는 게 특징입니다. StrictMode를 켜거나 동시성 기능을 쓰기 시작할 때 터집니다.

## 핵심 3가지

- **컴포넌트는 문자 그대로 함수입니다.** 렌더될 때마다 처음부터 다시 실행되고, 안의 변수와 함수는 전부 새로 만들어집니다.
- **순수해야 하는 건 계약입니다.** React가 렌더를 중단하고 재개하고 두 번 부를 수 있는 대가입니다.
- **렌더는 스냅샷입니다.** `setState`를 연달아 불러도 같은 옛 값을 봅니다. 이때는 함수형 업데이트를 쓰세요.
