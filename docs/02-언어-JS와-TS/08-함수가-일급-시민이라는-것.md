# 8. 함수가 일급 시민이라는 것 — 클로저와 배열 메서드

> **이 장의 질문**: "함수가 값이다"라는 말은 실제로 코드를 어떻게 바꾸는가?

## BE로 치면 이런 것

Java 8의 람다와 Stream API를 떠올리세요. `list.stream().filter(...).map(...).collect(...)`. 그게 나오기 전과 후로 Java 코드가 달라졌죠.

JavaScript는 처음부터 그렇게 만들어졌습니다. 함수는 특별한 문법이 아니라 **그냥 값** 입니다. 숫자를 변수에 담듯 함수를 담고, 문자열을 넘기듯 함수를 넘깁니다.

```js
const double = (x) => x * 2;        // 변수에 담기
[1, 2, 3].map(double);              // 인자로 넘기기
const makeAdder = (n) => (x) => x + n;  // 함수가 함수를 반환
```

React 코드는 이 세 가지로 거의 다 이루어져 있습니다. 그래서 이 장이 필요합니다.

## 화살표 함수

함수를 만드는 문법이 두 가지 있습니다. 아래 셋은 **이 예제에서는** 같은 결과를 냅니다.

```js
// 1) function 키워드 — 요즘은 잘 안 씀
function add(a, b) { return a + b; }

// 2) 화살표 함수 — 표준
const add = (a, b) => { return a + b; };

// 3) 본문이 한 줄이면 중괄호와 return 생략
const add = (a, b) => a + b;
```

**항상 같지는 않습니다.** `function` 선언은 호이스팅되고 `this`가 호출 방식에 따라 정해지지만(7장), 화살표 함수는 호이스팅되지 않고 `this`를 바깥에서 물려받습니다. **실무에서는 화살표 함수를 기본으로 쓰면 이 차이를 신경 쓸 일이 거의 없습니다.**

Kotlin의 `val add = { a: Int, b: Int -> a + b }` 와 같습니다.

주의할 함정 하나. **객체를 반환할 때는 괄호로 감싸야 합니다.**

```js
const makeUser = (name) => ({ name });   // ✅ 괄호 필수
const makeUser = (name) => { name };     // ❌ 중괄호를 블록으로 해석 → undefined 반환
```

## 배열 메서드 — Stream API 대응표

실무 코드의 절반은 배열 변형입니다. Stream API와 나란히 놓으면 바로 읽힙니다.

| JavaScript | Java Stream | 반환 |
| --- | --- | --- |
| `arr.map(f)` | `.map(f).collect(toList())` | 새 배열 |
| `arr.filter(f)` | `.filter(f).collect(toList())` | 새 배열 |
| `arr.reduce(f, init)` | `.reduce(init, f)` | 값 하나 |
| `arr.find(f)` | `.filter(f).findFirst()` | 첫 요소 또는 `undefined` |
| `arr.some(f)` | `.anyMatch(f)` | boolean |
| `arr.every(f)` | `.allMatch(f)` | boolean |
| `arr.flatMap(f)` | `.flatMap(f)` | 평탄화된 배열 |
| `arr.sort(f)` | `.sorted(f)` | ⚠️ **원본을 바꿈** |
| `arr.includes(x)` | `.contains(x)` | boolean |

**어긋나는 지점 두 가지:**

1. **`.stream()`과 `.collect()`가 없습니다.** 배열에 바로 메서드가 달려 있고 바로 배열이 나옵니다.
2. **지연 평가가 아닙니다.** `filter` 다음 `map`을 하면 중간 배열이 실제로 만들어집니다. 백만 건이면 신경 써야 하지만, 화면에 그릴 정도의 데이터에서는 문제되지 않습니다.

```js
// 배송 완료된 주문의 총액
const total = orders
  .filter(o => o.status === 'DELIVERED')
  .map(o => o.amount)
  .reduce((sum, amount) => sum + amount, 0);
```

```kotlin
// Kotlin
val total = orders
  .filter { it.status == Status.DELIVERED }
  .sumOf { it.amount }
```

**`sort`만은 조심하세요.** 원본 배열을 직접 바꿉니다. React에서 이건 버그의 원인이 됩니다.

```js
const sorted = [...orders].sort((a, b) => a.amount - b.amount);  // ✅ 복사 후 정렬
```

또 하나. **`sort()`는 기본이 문자열 비교입니다.**

```js
[10, 9, 1].sort()                      // [1, 10, 9]  😱
[10, 9, 1].sort((a, b) => a - b)       // [1, 9, 10]  ✅
```

## 불변으로 다루기 — 전개 구문

React가 변경을 감지하는 방식(참조 비교, 7장) 때문에, 프론트엔드에서는 **원본을 고치지 않고 새 것을 만드는** 방식이 기본입니다.

```js
// 객체 — 한 필드만 바꾼 새 객체
const updated = { ...order, status: 'SHIPPED' };

// 배열 — 추가
const added = [...orders, newOrder];

// 배열 — 삭제
const removed = orders.filter(o => o.id !== targetId);

// 배열 — 특정 요소만 교체
const replaced = orders.map(o => o.id === targetId ? { ...o, status: 'SHIPPED' } : o);
```

Kotlin의 `data class`와 `copy()`가 하는 일을 `...`가 합니다.

```kotlin
val updated = order.copy(status = Status.SHIPPED)
```

**주의: 얕은 복사입니다.** 중첩된 객체는 여전히 같은 참조를 공유합니다.

```js
const copy = { ...order };
copy.customer.name = '이';   // ⚠️ 원본의 customer도 바뀐다
```

중첩이 깊어지면 코드가 지저분해지는데, 그건 대개 **상태 구조를 평평하게 만들라는 신호** 입니다. 26장에서 다룹니다.

## 클로저

**클로저는 "함수가 자기가 만들어진 곳의 변수를 기억하는 것"입니다.**

```js
function makeCounter() {
  let count = 0;                    // 이 변수는
  return () => ++count;             // 반환된 함수가 계속 기억한다
}

const next = makeCounter();
next();  // 1
next();  // 2
```

`makeCounter`는 이미 끝났는데도 `count`는 살아 있습니다. Java의 람다가 캡처를 하는 것과 같은데, **결정적인 차이가 하나 있습니다.**

| | Java | JavaScript |
| --- | --- | --- |
| 캡처하는 변수 | 재할당 불가 (effectively final) | 재할당 가능 |
| 변수에 **다른 값을 대입**하면 | 애초에 못 함 | **람다에서 보임** |
| 담긴 **객체의 내용**을 바꾸면 | 보임 | 보임 |

즉 "Java는 값, JS는 변수"라고 외우면 절반만 맞습니다. 정확히는 **재할당이 보이느냐** 의 차이이고, 객체 내용 변경은 양쪽 다 보입니다.

이 차이가 React에서 실제 버그를 만듭니다. 19장에서 "오래된 클로저(stale closure)"라는 이름으로 다시 만나게 되는데, 미리 감을 잡아 둡시다.

```js
// 흔한 함정: 반복문 안에서 만든 함수들이 같은 변수를 공유한다
const fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => console.log(i));
}
fns.forEach(f => f());   // 3, 3, 3  😱 — var는 함수 스코프라 i가 하나뿐

// let을 쓰면 반복마다 새 변수가 생긴다
for (let i = 0; i < 3; i++) { ... }   // 0, 1, 2  ✅
```

`var`를 쓰지 말라는 이유가 이것입니다.

## 콜백 — 함수를 넘기는 이유

함수를 인자로 받으면 **"무엇을 할지"를 호출자가 정하게** 됩니다.

```js
// 이 함수는 "실패했을 때 무엇을 할지" 모른다. 부르는 쪽이 정한다.
function retry(task, onFail) {
  try { return task(); }
  catch (e) { onFail(e); }
}

retry(loadOrders, (e) => console.error('불러오기 실패:', e.message));
```

전략 패턴을 인터페이스 없이 하는 셈입니다. Java에서 `Runnable`, `Consumer<T>`, `Function<T,R>` 인터페이스를 만들어 넘기던 것을 그냥 함수로 합니다.

> **미리 알아두기**: 나중에 배울 React에서 컴포넌트끼리 대화하는 방식이 정확히 이것입니다. 부모가 자식에게 함수를 내려주고, 자식이 그 함수를 부릅니다. 17장에서 다시 만납니다.

## 흔한 오해

**"화살표 함수는 짧게 쓰려는 문법 설탕이다"**
`this` 동작도 다릅니다(7장). 그리고 실무에서는 그냥 화살표 함수를 기본으로 씁니다.

**"map은 forEach보다 좋다"**
용도가 다릅니다. **새 배열이 필요하면 `map`, 부수 효과만 필요하면 `forEach`** 입니다. 반환값을 안 쓰면서 `map`을 쓰면 린터가 잡습니다.

**"불변으로 다루면 느리지 않나"**
화면에 그릴 규모의 데이터에서는 무시할 수준입니다. 그리고 그 대가로 React가 변경 감지를 아주 싸게 할 수 있습니다.

## 핵심 3가지

- **함수는 값입니다.** 변수에 담고, 인자로 넘기고, 반환합니다. React 코드는 거의 이것으로만 이루어져 있습니다.
- **배열 메서드는 Stream API와 짝이 맞습니다.** 다만 지연 평가가 없고, `sort`는 원본을 바꿉니다.
- **불변으로 다룹니다.** 전개 구문으로 복사해서 새로 만드세요. Kotlin `data class`의 `copy()` 자리입니다.
