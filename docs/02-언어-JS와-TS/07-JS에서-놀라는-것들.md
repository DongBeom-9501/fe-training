# 7. JS에서 놀라는 것들

> **이 장의 질문**: Java/Kotlin을 하던 사람이 JavaScript에서 처음 헛디디는 곳은 어디인가?

이 장은 문법 강의가 아닙니다. `if`, `for`, 함수 정의처럼 똑같이 생긴 것들은 건너뜁니다. **다르게 생겼거나, 같아 보이는데 다르게 동작하는 것** 만 모았습니다.

## BE로 치면 이런 것

새 언어를 배울 때 진짜 위험한 건 완전히 낯선 문법이 아닙니다. 그건 어차피 찾아보게 되니까요. 위험한 건 **익숙한 모양인데 뜻이 다른 것** 입니다. JavaScript에는 그런 게 몇 개 있고, 그것들이 실무 버그의 큰 지분을 차지합니다.

## 1. 값이 없다는 상태가 두 개다

Java에는 `null` 하나뿐입니다. JavaScript에는 둘입니다.

```js
let a;              // undefined — "아직 값이 담긴 적 없음"
let b = null;       // null      — "없다고 명시적으로 정함"
```

| 상황 | 결과 |
| --- | --- |
| 선언만 하고 대입 안 함 | `undefined` |
| 객체에 없는 키 접근 | `undefined` |
| 함수에 인자를 안 넘김 | `undefined` |
| 함수가 아무것도 반환 안 함 | `undefined` |
| 개발자가 "없음"을 표현 | 보통 `null` |

**실무 규칙**: `undefined`는 시스템이 만드는 것, `null`은 사람이 만드는 것으로 생각하세요. 그리고 **직접 코드를 쓸 때는 둘을 구분하려 애쓰지 말고 `undefined` 하나로 통일하는 편** 이 편합니다 (서버가 `null`을 내려주는 것은 어쩔 수 없고요).

이 둘을 한꺼번에 다루는 문법이 두 개 있는데, 실무에서 매일 씁니다.

```js
// ?. — 앞이 null이나 undefined면 거기서 멈추고 undefined를 반환
const city = user?.address?.city;
// Kotlin의 user?.address?.city 와 동일

// ?? — 앞이 null이나 undefined일 때만 오른쪽 값 사용
const name = user.name ?? '이름 없음';
// Kotlin의 user.name ?: "이름 없음" 과 동일
```

## 2. `==`를 쓰면 안 되는 이유

```js
0 == '0'        // true   😱
0 == false      // true   😱
null == undefined // true
'' == 0         // true   😱

0 === '0'       // false  ✅
0 === false     // false  ✅
```

`==`는 비교 전에 타입을 알아서 변환합니다. 그 변환 규칙이 직관과 어긋나는 경우가 많아서, **실무에서는 `===`만 씁니다.** 린터가 `==`를 에러로 잡도록 설정하는 게 표준입니다. (23장)

예외는 딱 하나, `x == null`은 "null이거나 undefined"를 한 번에 검사하는 관용구로 인정되기도 합니다. 다만 `x ?? y`나 `x != null`을 쓰는 편이 요즘 스타일입니다.

## 3. truthy와 falsy

`if` 안에 boolean이 아닌 값을 넣을 수 있고, 그러면 이 규칙이 적용됩니다.

**falsy는 이 여섯 개뿐입니다.** 나머지는 전부 truthy입니다.

```
false, 0, '' (빈 문자열), null, undefined, NaN
```

빈 배열 `[]`과 빈 객체 `{}`가 **truthy** 라는 점을 주의하세요. Kotlin의 `isEmpty()` 감각으로 접근하면 틀립니다.

```js
if ([]) console.log('실행됨');    // 빈 배열도 truthy!
if (orders.length) { ... }        // ✅ 이렇게 써야 한다
```

가장 흔한 버그는 숫자 0입니다.

```js
// 나쁜 예: count가 0이면 "0건"이 아니라 "-"가 나온다
const label = count ? `${count}건` : '-';

// 좋은 예
const label = count != null ? `${count}건` : '-';
```

## 4. `number`는 한 종류뿐이다

`int`, `long`, `double` 구분이 없습니다. `number` 타입은 **전부 64비트 부동소수점** 입니다.

```js
0.1 + 0.2 === 0.3     // false (0.30000000000000004)
9007199254740993      // 정밀도 손실 시작
```

백엔드에서 `Long` ID를 쓰고 있다면 이건 실제 문제가 됩니다. `Long.MAX_VALUE` 근처의 ID를 JSON으로 내려주면 JavaScript에서 값이 뭉개집니다.

정수를 정확히 다뤄야 할 때를 위해 **`BigInt`** 라는 별도의 원시 타입이 따로 있습니다. 다만 `number`와 섞어서 연산할 수 없어서, 쓰기로 했다면 그 값은 끝까지 `BigInt`로 다뤄야 합니다.

> **실무 규칙**: 서버가 64비트 정수 ID나 금액을 내려줄 때는 **문자열로 직렬화**하세요. 계산이 필요하면 `BigInt`나 decimal 라이브러리를 씁니다. 37장에서 다시 다룹니다.

## 5. 객체와 배열은 참조다

```js
const a = { count: 1 };
const b = a;
b.count = 2;
console.log(a.count);   // 2 — a도 바뀌었다
```

Java와 같습니다. 놀랄 일이 아니죠. 놀라운 건 **`const`가 이걸 막지 않는다** 는 점입니다.

```js
const user = { name: '김' };
user.name = '이';    // ✅ 허용된다
user = {};           // ❌ 이것만 막힌다
```

`const`는 Kotlin의 `val`과 같습니다. **재할당만 막고 내용 변경은 막지 않습니다.** 진짜 불변이 필요하면 복사해서 새 객체를 만드는 방식으로 다룹니다 (8장).

이게 왜 중요하냐면 — **React는 "객체가 바뀌었는지"를 참조 비교로 판단합니다.** 내용만 바꾸고 같은 객체를 넘기면 React는 안 바뀐 줄 압니다. 18장에서 반드시 다시 만납니다.

## 6. `this`는 호출 방식이 정한다

Java에서 `this`는 항상 "이 인스턴스"입니다. JavaScript에서 `this`는 **어떻게 호출됐느냐** 로 정해집니다.

```js
const user = {
  name: '김',
  greet: function () { console.log(this.name); }
};

user.greet();              // '김'   — user.으로 불렀으니 this는 user
const f = user.greet;
f();                       // 💥 TypeError — this가 undefined라서 this.name을 못 읽음
```

혼란스럽습니다. 그래서 **해결책은 간단합니다: 화살표 함수를 쓰고, `this`를 안 쓰면 됩니다.**

```js
const greet = () => console.log(user.name);   // this 안 씀
```

모던 React는 함수 컴포넌트만 쓰기 때문에 `this`를 쓸 일이 거의 없습니다. 오래된 코드(클래스 컴포넌트)를 읽을 때만 필요한 지식이라, **이 정도만 알고 넘어가도 충분합니다.**

## 7. `var`는 쓰지 않는다

```js
var  // 함수 스코프, 재선언 가능, 호이스팅됨 — 쓰지 마세요
let  // 블록 스코프, 재할당 가능
const // 블록 스코프, 재할당 불가 ← 기본값으로 쓰세요
```

**기본은 `const`, 재할당이 필요할 때만 `let`, `var`는 절대.** 린터가 강제합니다.

## 8. 문자열은 백틱을 쓴다

```js
const msg = `주문 ${orderId}건, 총 ${price}원`;
// Kotlin의 "주문 ${orderId}건" 과 동일
```

여러 줄도 그냥 됩니다. 실무 코드의 문자열은 대부분 백틱입니다.

## 9. 동등성 비교에는 `equals`가 없다

```js
{ a: 1 } === { a: 1 }    // false — 참조가 다르니까
[1, 2] === [1, 2]        // false
```

값 비교를 하려면 직접 비교하거나 라이브러리를 씁니다. 다만 **실무에서는 깊은 비교를 하는 것 자체가 설계 신호** 인 경우가 많습니다 — "왜 두 객체를 비교해야 하지?"를 먼저 물어보세요.

## 흔한 오해

**"JS는 타입이 없다"**
타입은 있습니다(`string`, `number`, `boolean`, `object`, ...). 변수에 타입이 고정되지 않을 뿐입니다. 그리고 11장에서 TypeScript로 고정시킵니다.

**"`==`도 알아두면 편할 때가 있다"**
없습니다. 코드베이스 전체에서 `===`만 쓰는 게 훨씬 이득입니다.

**"`const`면 안전하다"**
재할당만 안전합니다. 내용은 얼마든지 바뀝니다.

## 핵심 3가지

- **"값 없음"이 둘입니다.** `undefined`는 시스템이, `null`은 사람이 만듭니다. `?.`와 `??`로 한꺼번에 다룹니다.
- **비교는 항상 `===`.** `==`의 타입 변환 규칙은 직관과 어긋납니다. 그리고 `0`과 빈 문자열이 falsy라는 점을 조심하세요.
- **`const`는 재할당만 막습니다.** 객체 내용은 얼마든지 바뀝니다. 이 성질이 나중에 React에서 중요해집니다.
